## MVVM (Model - View - ViewModel)

#MVVM 의 핵심 개념에 대해 알아보자.  
MVVM에 대해 알아보기전에 #MVC 에 대해 먼저 알아보자.

### MVC (Model-View-Controller)

![[Pasted image 20250727183604.png]]

화살표는 누가 무엇을 알고있느냐를 표현한 것.  
컨트롤러는 모델에서 데이터를 가져와 View에게 데이터를 가공해서 전달한다.  

```txt
- View는 유저의 인터렉션을 받아 모델을 갱신한다. 
- View는 어떤 Model을 갱신해야하는지 알고있다.
- View가 Model을 알고있는게 무엇이 문제일까?  
- 이게 가장 큰 문제를 일으킨다 .  
- 모델은 비즈니스 도메인에 관련된 내용이다.  
- 뷰는 화면이 이쁘냐 안이쁘냐 이런것에 관심이 있고 유저 인터렉션과 관련된 부분을 담당한다.
- 여기서 뷰와 모델이 알고있다는 것이 MVC의 약점이다.  
- MVC는 백엔드에서 주로 선호한다.  
```

프론트엔드에서는 양방향으로 흐르기떄문에 MVC가 적합하지 않다.  
Model의 변경이 View의 변경을 간접적으로 야기하기 때문

### 제왕적 MVC

![[Pasted image 20250727185359.png]]

```txt
- 컨트롤러가 왕이다.
- 컨트롤러가 뷰와 모델을 모두 알고 있다.
- 모델이나 뷰의 변경이 일어난다면 컨트롤러의 변화가 생긴다. (비대해진다)
- 컨트롤러에 대한 의존성이 굉장히 심하기 때문에 유지보수가 어려워진다.
```

### MVP (Model-View-Presenter)

![[Pasted image 20250727185424.png]]

```txt
- View의 getter, setter가 노출되어 있다.
- View에는 순수한 getter, setter만 존재한다.
- Presenter에서 View에서 getter, setter를 통해 컨트롤 한다.
- View하나를 만들기위해 getter, setter를 만들어야한다.
- MVP를 하게되면 하나의 View를 만들때마다 getter, setter를 작성해야한다. (부담)
```

### MVVM (Model-View-ViewModel)

![[Pasted image 20250727190150.png]]

```txt
- MVVM이 성립하기 위해서는 `Binder`가 있어야 한다. 그렇지 않으면 성립하지 않는다.
- Binder가 없으면 많은 문제가 해결되지 않는다.

- 핵심적으로 알아야할 ViewModel
- ViewModel이 뭔데? = 순수환 View라고 볼 수 있다.
- 진짜 그대로의 View가 아니라 순수한 데이터로서의 View
- 즉 DOM을 다루지 않는다.

- ViewModel을 가지고 실제 View와 Binder가 자동으로 ViewModel의 변화를 감지해서 View에 반영되기를 바라거나
- View의 변화를 Binder를 타고 ViewModel을 갱신하거나,
- 즉 이 과정을 자동화해주는 Binder가 없으면 화면의 갱신이 이러나지 않을 것.
- 이때문에 Binder가 없으면 MVVM이 성립하지 않는다고 이야기한 것
- Binder가 View와 ViewModel의 의존성을 없애주는 역할을 한다.


- 두번째 핵심
- ViewModel은 View를 모른다.
- ViewModel은 View를 알고있으면 MVVM이 아니다.
- 양방향 바인딩이란 observe가 어디에 걸려있느냐의 차이

```

>[!info] 핵심 정리
>- ViewModel은 순수한 데이터로서의 View이다.
>- ViewModel과 View는 서로를 모른다.

## TypeCheck

```js
const type = (target, type) => {  
  if(typeof type === 'string') {  
    if(typeof target != type) {  
      throw `invalid type ${target} : ${type}`  
    }  
  } else if (!(target instanceof type)) {  
    throw `invalid type ${target} : ${target}`  
  }  
  return target;  
}  
  
console.log(type(123, 'number'))  
// console.log(type(123, 'string'))  
console.log(type('123', 'string'))  
console.log(type([], 'object'))  
console.log(type({}, 'object'))  
console.log(type([1,2,3], Array))  
console.log(type(new Set, Set))
```

javascript는 컴파일언어가 아니기 때문에, 런타임에 throw하지 않으면 오류가 전파된다.  
기본적으로 throw를 던져놓고 throw하는 부분만 부드럽게 처리하는 방식으로 처리한다.  
그만큼 throw를 던져야 디버깅하기에 수월하다.  

```js
const test = (arr, _ = type(arr, Array)) => {  
  console.log(arr)  
}  
  
test([1, 2, 3, 4])  
// test(123) // error  
  
const test2 = (a, b, c, _0 = type(a, 'string'), _1 = type(b, 'number'), _2 = type(c, 'boolean')) => {  
  console.log(a, b, c)  
}  
  
test2('abc', 123, true)
```

위와같이 매개변수를 검사하여 큰 실수를 막을 수 있다.

## View hook & bind

View에는 어떤 ViewModel과 매칭할지에 대한 별도의 hook이 필요하다.

```html
<section id="target" data-viewmodel="wrapper">
	<h2 data-viewmodel="title"></h2>
	<section data-viewmodel="contents"></section>
</section>
```


여기서는 [`data-*`](https://developer.mozilla.org/en-US/docs/Web/HTML/How_to/Use_data_attributes) 를 사용하여 `wrapper`, `title`, `contents` 라는 hook을 추가한다.  
이후 binder를 통해 ViewModel의 속성과 일치하는 녀석들을 매핑한다.   
ViewModel에는 `wrapper`, `title`, `contents`과같이 hook과 매칭되는 녀석들이 있을 것이다.
